## 1. 교안과 준비 (새벽~10시)
**한 일**
1. 새벽에 체크리스트처럼 기능정의를 보면 좋겠다고 생각해서 엑셀 파일의 기능 표를 정리했다. 같은 계정 파트 팀원분께 확인용으로 필요하시면 쓰시라고 공유했다.
2. 로그인 폼을 조금 고치고, 대강 만들어진 교안에 기능정의 우선순위와 수정된 목업을 주었다. 실무 체험을 위한 프로젝트이니 실무 순서에 가까운 교안으로 다시 만들어 달라고 요청했다.
3. 강사님이 주신 API 문서(`AUTH_EMAIL_LOGOUT_API.md`)와 Swagger로 회원가입·로그인 API 모양을 확인했다.
4. 아이디 로그인을 하고 싶었지만, 강사님 API가 이메일로만 로그인을 받아서 강사님과 이야기한 뒤 **로그인 아이디 = 이메일**로 통일했다.
5. 교안 중간중간에 `add`와 커밋명을 추천받아 넣었다. 커밋명을 그렇게 쓴 이유도 같이 넣어 공부가 되게 했다.


## 2. 화면 만들기 (11시~3시)
**무엇을 확인하려는가** : 공통 부품(버튼, 입력 칸)과 가짜 API로, 진짜 API 없이도 로그인·회원가입 화면을 먼저 완성할 수 있는가

**한 일**
1. 교안을 보며 하나하나 손으로 쳤다. 느려서 Copilot 고스트 텍스트를 켜고 자동완성을 쓰며 진행했고, 궁금한 건 중간중간 AI에게 물었다.
2. 공통 부품(`Button`, `Alert`, `TextField`, `PasswordField`)을 먼저 만들고 커밋했다. 1시 중간 보고 뒤 PR #19로 develop에 머지했다.
3. 가짜 API(`mockAuthApi`)와 로그인 화면을 만들었다. 입력 요청 문구가 뜰 때 상자가 들썩이는 게 싫어서, 문구 자리를 미리 비워 두도록 고쳤다.
4. 3시부터는 시간상 팀에 폐가 될 것 같아 복사 붙여넣기로 바꿨다. 진짜 궁금한 것만 묻고, 코드 리뷰는 TIL 쓰면서 하기로 했다.

⚠️ 아이디·비밀번호 입력에 필요한 신기한 부품들(자동 중복 확인, 비밀번호 강도 등)이 본격적으로 나온 게 이때부터라 아쉬웠다. 하지만 협업이 우선이라고 생각했다.

## 3. API 연결과 머지 (4시~6시)
**무엇을 확인하려는가** : 만들어 둔 겉껍질에 강사님 Spring API를 붙일 준비가 되는가

**한 일**
1. 회원가입 4단계 화면을 커밋했다. 마음에 들지 않는 구조(비밀번호 강도 막대 간격 등)는 AI에게 고치는 방법을 조언받고 직접 고쳤다. 복사 붙여넣기를 하면서도 교안의 설명글은 계속 읽었다.
2. Swagger에서 직접 가입(200), 같은 이메일로 다시 가입(409), 로그인 성공(200), 로그인 실패(401)를 눌러 봤다.
3. 완성된 겉껍질에 API 연결을 시작했다. 5시 30분까지 API 완전 연결 직전까지의 코드(NextAuth 설정, 강사님 API 호출 도구, 로그인 상태 표시)를 입력했다.
4. proxy가 정상 작동하는 것을 확인했지만, 비회원도 써야 할 채팅창이 완전히 막혀서 일단 꺼 두었다. 어디까지 막을지 채팅·포스트 팀과 상의가 필요하다.
5. 팀원들과 모여 파트 간 머지와 develop PR을 했다(PR #28). 머지 중 `app/layout.tsx` 충돌을 고치고 사라진 `AuthShell`을 다시 넣어 한 번 더 PR했다(PR #29).
6. 헤어진 뒤 엑셀 시트로 돌아가 로컬 서버에서 내가 구현한 것을 테스트하며 체크리스트를 확인했다. 남은 것은 12일 교안으로 따로 정리했다.

## 5. 오늘의 난관 (회고)
- 손코딩이 느렸다. 지식욕을 채우는 것도 중요하지만 협업인 만큼 지연으로 민폐를 끼치고 싶지 않아, 점심 후 바로 코딩을 재개했고 3시부터는 복사 붙여넣기로 바꿨다.
- 줄끝 문자(LF/CRLF)는 예전부터 늘 귀찮았다. 한 번 조정했는데도 다시 나와서 Source Control 탭에서 손으로 하나하나 정리했다. 나중에 LF로 일괄 설정을 해야겠다.
- 팀원분들께 "Mongo 유저 id를 쓰면 된다"고 말씀드렸지만, 내 지식이 부족한 만큼 모호한 대답이 되었을지도 모르겠다. 공부가 부족하다.
- 머지할 때 패키지 충돌과 `app/layout.tsx` 충돌이 있었다. 급히 넣은 `AuthShell`이 잘못되어 있었고, 다른 파트분의 Suspense import 위치가 나와 달라 중복이 생긴 것 같았다.
- 아직 모르는 게 산더미라 유경험자분들과 소통하기가 어렵다. 개발자로서 당연하게 염두에 두어야 하는 것들이 아직 머릿속에 체계가 잡히지 않아서일지도 모르겠다.

### 11시 : 본격적인 코드 작성

- 강사님 Swagger API 테스트 후 본격적인 코드 작성을 시작했다.
- 교안을 보며 하나하나 작성하다가 느림을 느끼고, Copilot 고스트 텍스트 설정을 켠 뒤 자동완성을 이용하며 진행했다. 중간중간 궁금한 게 있으면 AI에게 질문했다.
- 중간에 팀원분께서 로그인 API와 스키마에 대해 문의하셔서 확인해 보니, 강의를 토대로 만드는 것이라 스키마를 크게 추가할 건 없었다. 다행이었다.
- 팀원분의 질문 덕분에 내 로그인 계정 방식이 어떻게 만들어지고 있는지 좀 더 자세히 알 수 있었다. 로그인 교신은 강사님의 Spring Boot 서버로 하고, 유저 정보는 지금 팀에서 쓰는 MongoDB에 저장하는 방식이다.

### 12시 : 손코딩과 줄끝 문자

- 하나하나 손코딩을 하다 보니 많이 느려서, 점심 식후 바로 코딩을 다시 시작했다.
  - 💭 내 지식욕을 채우는 것도 중요하지만, 팀원들과 협업하는 만큼 지연으로 민폐를 끼치고 싶지 않았다.
- 줄끝 문자(LF/CRLF)는 예전부터 늘 귀찮았는데, 한 번 조정했는데도 나중에 다시 나와서 그냥 Source Control 탭에서 손으로 하나하나 정리했다.
  - 줄끝 문자는 맥과 윈도우 같은 운영 체제 차이로 줄바꿈을 표시하는 방식이 달라서 생기는 것 같다. 나중에 LF 방식으로 일괄 설정을 하든가 해야겠다.

### 1시 : 중간 보고와 PR, 유저 id

- 1시에 팀원들 모두 모여 중간 보고를 한 뒤, 파트별로 머지하고 develop 브랜치에 PR을 했다.
  - 💭 나도 다른 분의 PR 승인을 해 보고 싶었는데 다들 손이 무척 빨랐다.
- PR 뒤에 서로에게 필요한 것에 대한 대화를 나눴고, 이전처럼 스키마 이야기가 나왔다. 이제 사용자가 채팅을 하고 커뮤니티에 글을 쓰려면 계정을 써야 하기 때문이다.
- 강사님 Spring Boot에서 오는 유저 정보로는 확실한 유저 구분이 어려우므로, MongoDB에 저장되는 유저마다 나오는 별도의 id를 쓰는 방향을 AI에게 설명받았다. 팀원분들께 MongoDB 유저 id를 쓰면 된다고 말씀드렸다.
  - 💭 그런데 지금 생각해 보면 내가 지식이 부족한 만큼 팀원들에게도 모호한 대답이 되었을지도 모르겠다. 공부가 부족하다..

### 2시 : 속도 내기

- 함께 계정 파트를 채우는 팀원분께서 일정상 공백이 있을 예정이셔서 속도를 내야 했다. 좀 더 빠르게 타이핑하려고 집중했다.

### 3시 : 복사 붙여넣기로 전환

- 열심히 손코딩을 했지만 시간상 팀원들에게 폐가 될 것 같았다. 이때부터는 복사 붙여넣기를 하며 진짜 궁금한 것만 간단히 묻고, 코드 리뷰는 TIL을 쓰며 확인하기로 했다.
  - 💭 이때쯤 아이디·비밀번호 입력에 필요한 신기한 부품들이 본격적으로 추가되던 참이라 아쉬웠지만, 역시 협업이 우선이라고 생각했다.

### 4시 : 구조 고치기와 API 연결 시작

- 만들면서 중간중간 마음에 들지 않는 구조는 AI에게 고치는 방법을 조언받고 직접 고쳤다.
- 그냥 복사 붙여넣기는 의미가 없다고 생각해서, 코드를 붙이는 한편으로 교안에 쓰여 있는 설명글은 계속 읽었다.
- 완성된 예비 겉껍질에 본격적으로 API 연결을 시작했다.

### 5시 : 연결 작업과 머지

- 30분까지 기초적인 연결 작업을 하고 proxy가 정상 작동하는 것을 확인했다.
- 비회원 유입 용도로도 써야 할 채팅창이 완전히 막히는 문제가 있어서, 나중에 proxy를 어디까지 걸지, 걸어도 되는지 채팅 팀, 포스트 팀과 상의가 필요하다.
- 우선 30분까지 API 완전 연결 직전까지의 코드를 입력했고, 팀원들과 모여 파트 간 머지와 develop PR을 했다.
- 중간에 패키지 충돌과 `app/layout.tsx` 충돌이 있었다. 패키지는 다른 분 것이라 레이아웃 쪽 충돌을 확인했다.
  - 마지막에 급히 넣었던 `AuthShell`이 잘못되어 있었고, 다른 파트분의 Suspense import 위치가 나와 달라 중복이 된 것 같았다.
  - 중복을 지우고, 머지 과정에서 사라진 `AuthShell`을 다시 넣은 뒤 PR했다.

### 6시 이후 : 체크리스트와 내일 준비

- 팀원들과 헤어진 뒤에는 다시 엑셀 시트로 돌아가, 내가 구현을 확인할 수 있는 것들을 로컬 서버에서 테스트하며 체크리스트를 확인했다. 필수 구현은 정말 얼마 남지 않았다.
- 마음 같아선 소셜 로그인도 구현하고 싶지만 시간 관계상 아쉬움으로 남겨 둔다. 프로젝트가 끝난 뒤 따로 완성해 보거나, 완성하고 싶어 하는 팀원분이 계시면 같이 고도화하면 좋을 것 같다.
- AI에게 오늘 진행 상황 정리를 받아 완료한 교안과 남은 교안을 확인했다. 필수 기능은 오전 중에 완성할 생각이라, 끝난 것은 치우고 못 한 것들을 12일용 교안으로 새로 정리했다.
- 필요하면 TIL을 다 쓴 뒤 MongoDB 안의 계정으로 로그인이 되도록 코드를 마무리할까 한다. 그러면 내일 회원가입 쪽과, 자리를 비우는 팀원분께 인계받을 내용, proxy까지 할 수 있지 않을까?
- 💭 느낀 점
  - 내 손이 느린 게 큰 맹점이고 후다닥 복붙을 할 수 없는 게 아쉽지만, 이 짧은 프로젝트 자체는 그래도 의미가 있었다고 생각한다. 프론트엔드 코드가 점점 즐거워지는 중이다. 물론 그것과 별개로 아직 모르는 게 산더미라 유경험자분들과의 소통에 어려움이 있긴 하지만!
    - 이 부분은 이전에 다른 프로젝트에 참여했을 때 실력자들 사이에 껴서 했을 때도 경험했던 부분이라 크게 위축되는 기분이 들진 않았지만, 그래도 조금 아쉽다. 개발자로서 당연하게 염두에 두어야 하는 것들이 무엇인지가 내 손발이 될 정도로 머릿속에 체계가 잡히지 않아 그럴지도 모르겠다. 이 부분은 아마 개발자로 취업했을 때도 소통에서 문제가 될 수 있을 것 같다. 개선될 수 있기를 희망한다.
