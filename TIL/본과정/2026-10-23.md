### AI가 지금 보고 있는 것은 무엇인가?
- AI는 내 머릿속을 자동으로 들여다보지 못함. RAG가 되어있지 않으면 하나하나 알려주어야 함.
- 대화 흐름
  - Context Window : 한 요청의 제한된 작업공간에서 이루어짐.
  - 질의응답 모두 토큰 : 질문이 많으면 답변량이 줄어들 수 있음. 요즘은 용량이 커져서 크게 걱정할 거 없음.
  - 사용자 PC ⇄ LLM API
    - 대화기록 : 프롬프트 캐싱
- 실제로 확인해보면 대화가 없어도 이어 들어가는 정보가 있음.
- So, 프롬프트 엔지니어링 시 좋은 법
  1. 잘 설명해야 함.
  2. But 좋은 지시뿐 아니라 근거도 필요함.
  3. RAG : 기반자료를 준다.
  4. 오픈북 테스트
  5. Context Engineering

## 요즘 개발자의 역할
- 잘 묻고 : Context Window > Prompt Engineering

> [!NOTE]
> - Context Window(컨텍스트 윈도우) = AI가 한 번에 볼 수 있는 작업 책상의 크기예요. 내 질문, 이전 대화, 첨부 자료, AI의 답변이 전부 이 책상 위에 올라가요.
> - 토큰 = AI가 글을 읽는 단위(글자 조각)예요. 책상 크기도 토큰으로 재요.
> - 노트의 "질문이 많으면 답변량이 줄어들 수 있음" = 질문과 답변이 같은 책상을 나눠 쓰기 때문이에요. 질문이 책상을 많이 차지하면 답변 자리가 줄어들어요. 요즘은 책상이 커져서 크게 걱정하지 않아도 된다는 게 강사님 설명이에요.
> - "AI는 내 머릿속을 들여다보지 못함" = AI는 책상 위에 올라온 것만 알아요. 내 사정이나 조건은 직접 적어 줘야 해요. 그래서 "나는 AI에 어디까지 맡겨보았나"의 1번이 "내 조건을 먼저 적는지" 예요.
>
> **사용자 PC ⇄ LLM API, 그리고 프롬프트 캐싱**
> - LLM API는 기본적으로 이전 대화를 기억하지 않아요. 그래서 채팅 앱이 질문할 때마다 지금까지의 대화 기록을 통째로 다시 보내요. 노트의 "대화가 없어도 이어 들어가는 정보가 있음"이 이 얘기예요.
> - 프롬프트 캐싱 = 매번 똑같이 보내는 앞부분(대화 기록, 기본 지시문)을 AI 쪽에서 잠시 저장해 두고 재사용하는 기술이에요. 같은 내용을 다시 읽지 않아도 되니 빠르고 저렴해져요.
>   - 비유: 단골 카페에서 "늘 먹던 걸로요" 하면 주문을 처음부터 다시 설명하지 않아도 되는 것.

- 근거를 찾고 : RAG > Context Engineering

> [!NOTE]
> - RAG = AI가 답하기 전에 관련 문서를 먼저 찾아서 책상에 올려 두는 방법이에요. 노트의 "오픈북 테스트"가 바로 이 비유예요.
> - Fine Tuning(파인튜닝) = 모델 자체를 추가로 학습시켜서 특정 분야에 맞게 고치는 방법이에요.
>   - RAG = 시험 볼 때 책을 펴 보게 해 주기 / 파인튜닝 = 시험 전에 공부를 더 시키기
> - Context Engineering(컨텍스트 엔지니어링) = 질문 문장만 다듬는 게 아니라, 책상 위에 무엇을 올릴지 전체를 설계하는 것이에요(지시문, 참고 자료, 이전 기록, 도구 결과 등). 노트의 "좋은 지시뿐 아니라 근거도 필요함"이 이 생각이에요.

- 맡긴 결과를 확인하기 : Tool Calling > Agent, Harness Engineering, 그 안의 Loop

> [!NOTE]
> - Tool Calling(도구 호출) = AI가 직접 답을 지어내는 대신, "이 도구를 이 값으로 실행해 줘"라고 요청하는 기능이에요. 웹 검색, 날씨 조회, 계산기 같은 것들이요.
>   - 노트의 "Tool은 json으로 규격에 맞춰 부름" = 요청을 정해진 양식(JSON) 으로 써야 프로그램이 알아들어요. 주문서 양식을 지켜야 주방이 요리할 수 있는 것과 같아요.
>   - 흐름: 도구명·인자 → 앱 실행 → 결과 → 답변 (노트의 "공통점")
> - MCP (Model Context Protocol) = 여러 도구를 AI에 연결하는 표준 규격이에요. 노트대로 발견하고(어떤 도구가 있는지) → 호출하고 → 결과를 받는 과정을 통일했어요. 콘센트 규격이 같으면 어떤 가전이든 꽂을 수 있는 것과 같아요.
> - Agent(에이전트) = 도구를 쓰면서 여러 단계를 스스로 처리하는 AI예요.
> - Harness(하네스) = 원래 말에 채우는 마구(고삐·안장) 를 뜻해요. AI에서는 모델 주위에 붙이는 실행 장치 전체를 말해요. 노트의 "Agent = 모델 + 하네스"가 이 뜻이에요.
>   - 하네스에 들어가는 것: 기록 검색, 조회 기능, 위치 동의, 실행 승인, 기록과 현재 조회 구분, 미확인 항목 대기 (노트 내용)
>   - 비유: 아무리 힘센 말(모델)이라도 고삐와 안장(하네스) 이 있어야 원하는 곳으로 안전하게 갈 수 있어요.
> - "모델과 서비스는 같은 것이 아님" = 같은 모델을 써도 하네스(프롬프트, 도구, RAG 등) 가 다르면 결과가 달라요. 같은 엔진이라도 자동차 설계에 따라 성능이 다른 것과 같아요.
