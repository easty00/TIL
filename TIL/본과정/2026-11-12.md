## 1. 필수 기능 마무리 (새벽~11시)
**무엇을 확인하려는가** : 2인분의 일(계정 + 인계받은 마이페이지)을 오전 안에 필수 기능까지 끝낼 수 있는가

**한 일**
1. 새벽에 Spring 로그인 API와 MongoDB 회원 연결, 아이디 로그인, 아이디 찾기까지 끝내 두고, 오늘 할 일을 필수 마무리 교안과 마이페이지 교안으로 정돈했다.
2. 9시에 새벽 작업을 팀원들과 이야기한 뒤 머지했다(PR #31·#32). 이제 Spring 서버 API로 가입된 계정만 쓸 수 있다고 전달했다.
3. 어제처럼 복사 붙여넣기 방식으로 속도를 냈다. 일정을 미리 정돈해 둔 덕분에, 팀원분이 중간에 요청하신 것을 먼저 하는 식으로 취사선택할 수 있었다.
4. 마이페이지의 하드코딩을 걷었다. 로그아웃이 세션을 지우게 하고, 비밀번호 변경을 연결하고, 닉네임 규칙을 회원가입과 맞췄다. 임시로 DB의 첫 회원을 돌려주던 `getCurrentUser()`도 로그인 세션 기준으로 바꿨다.
5. 커뮤니티 팀이 내 마이페이지로 진행할 일이 있어, 보통 11시인 PR을 10시에 중간으로 한 번 더 했다(PR #33).
6. 헤더에 로그인 버튼과 내 이름 첫 글자를 넣고, 회원가입에 아이디 입력·중복 확인과 Spring API 연결을 했다. 비밀번호 찾기는 시간이 없어 AI가 넣었다. 진짜 이메일로 가입해서 보안키 메일도 받아 봤다.
7. proxy를 글쓰기만 막도록 완화하고, 11시에 PR #37로 필수 기능을 마쳤다.

## 2. 비회원과 null (13시)
**무엇을 확인하려는가** : 로그인하지 않은 사람이 들어와도 서비스가 깨지지 않고 로그인으로 자연스럽게 이어지는가

**한 일**
1. 점심 뒤 배포를 시작하자, 문제없을 거라 생각했던 비회원의 null 값이 말썽이었다.
2. 11시 무렵 내 PR이 들어가는 타이밍과 다른 파트가 새 브랜치를 내는 타이밍이 엇갈려, 한 브랜치의 커밋이 과거 코드를 가져오는 문제도 있었다. 그쪽은 무사히 해결되었다.
3. `getCurrentUser()`가 null을 돌려주는 경우를 확인했다. 헤더는 로그인 출입증만 보고, `getCurrentUser()`는 DB 회원까지 확인해서 "반쯤 로그인"된 상태가 생길 수 있었다.
4. 채팅 입력창 자리에 "로그인이 필요해요 + 로그인하러 가기" 말풍선을 띄웠다.
5. AI가 묻지 않고 게시판까지 말풍선으로 막아서 되돌렸다. 게시판은 글 목록 API만 비회원도 통과하게 고쳐서, 읽기는 되고 쓰기만 로그인이 필요하게 했다.
6. develop을 다시 받아 검사한 뒤 PR #44로 머지했고, 이후 배포에 성공했다.
7. 팀원분 요청으로 미구현 간편로그인 버튼을 오류 없이 주석 처리했다(PR #45).

| 곳 | 비회원 |
|---|---|
| 채팅 | 화면은 보이고, 입력창 자리에 로그인 안내 말풍선 |
| 게시판 | 글 목록·상세 읽기 가능, 수정·삭제 버튼 숨김 |
| 글쓰기 `/posts/new` | proxy가 로그인으로 보냄 |
| 댓글·좋아요 | "로그인 후 게시판을 이용해 주세요." 알림 |
| 마이페이지 | 페이지가 로그인으로 보냄 |

## 3. 미뤄 둔 기능과 정리 (14시~16시)
**무엇을 확인하려는가** : 팀에 큰 영향을 주지 않고, 필수가 아니라 넘겼던 보안·마이페이지 부속 기능을 채울 수 있는가

**한 일**
1. 필수가 아니라 미뤄 둔 것을 한 교안에 모았다. 파트 A 계정, 파트 B 마이페이지로 나눴다.
2. 마이페이지에서 바꾼 사진이 오른쪽 위 프로필 동그라미에 안 뜨는 문제를 고쳤다. 헤더가 원래 이름 첫 글자만 그리고 있어서, 팀원분이 만든 사진 주소를 헤더에서도 쓰게 했다.
3. 로그아웃할 때 Spring 서버 토큰도 무효화하게 했다(A-1).
4. 첫 로그인이 동시에 일어날 때 중복 막힘으로 로그인이 실패하지 않게 한 번 더 시도하고(A-2), 출입증은 유효한데 DB 회원이 없는 "어중간한" 상태면 자동 로그아웃되게 했다(A-3).
5. 교안 A-3이 헤더 사진 수정 **전** 코드 기준으로 쓰여 있는 걸 발견해서, 교안에 추가 수정 절을 달고 옛 블록에 경고를 붙였다.
6. 마이페이지 내 활동을 이름 대신 회원 번호로 비교해 내 것만 보이게 하고(B-1), 회원탈퇴는 관리자 문의 안내로 바꿨다(B-2). 문구는 직접 바꿨다.
7. 코드 리뷰를 하던 팀원분의 요청으로 Auth 파트 코드 전체를 훑어 주석을 정리했다. 남이 넣은 주석은 남기고, 내 주석도 꼭 필요한 것은 남겼다.
8. Problems 창의 노란 경고가 신경 쓰여서, 경고를 내던 Tailwind 클래스를 표준 이름으로 바꿨다(`gap-[18px]` → `gap-4.5`처럼). 38개에서 3개로 줄었다.
9. 팀 레포 `docs/auth.md`를 현재 상황으로 새로 쓰고 PR #47·#49로 머지했다.

### 9시 : PR과 getCurrentUser

- 지난 새벽 작업한 것을 팀원들과 이야기한 뒤 머지를 진행했고(PR #31·#32), 이제 Spring 서버의 API로 가입된 계정만 사용할 수 있음을 전달했다.
- 안전하게 PR 작업들을 완료한 뒤, 어제처럼 복사 붙여넣기 방식으로 빠르게 정리를 시작했다. 2인분인 만큼 속도를 내야 했기 때문이다.
- 다행히 지난 새벽에 미리 로그인 작업을 완료하고 오늘의 코드 작업 일정을 정돈해 둔 덕분에, 중간에 팀원분이 요청해 주신 걸 먼저 한다든가 하는 취사선택을 하며 작업을 진행할 수 있었다.
- 마이페이지의 하드코딩을 걷어 냈다. 로그아웃이 세션을 지우게 하고, 비밀번호 변경을 연결하고, 닉네임 규칙을 통일했다.
- 💭 오늘의 중요 함수는 `getCurrentUser()`였다. 이것 때문에 머리가 아팠다.

### 10시 : 중간 PR과 proxy

- 보통은 11시가 PR 시간이지만, 오늘은 11시에 마무리하기로 한 것도 있고, 내가 마무리한 마이페이지로 커뮤니티 팀에서 진행할 사안이 있어 중간에 PR을 진행했다(PR #33).
- 헤더에 로그인 버튼을 넣고, 회원가입에 아이디와 Spring API를 연결했다. 비밀번호 찾기는 시간이 없어 AI에게 맡겼고, 진짜 이메일로 가입해 보안키 메일도 받아 봤다.
- 그리고 여기서 한 번 스노우볼이 굴렀다.
  - 나는 비회원이 주요 기능을 사용하지 못하더라도, 우리가 만든 서비스에 유입되려면 겉 화면이라도 볼 수 있어야 한다고 생각했다.
  - 💭 시간 여유가 있었다면 현재 운영되고 있는 LLM들처럼 비회원에게도 하루에 소량의 무료 토큰을 주자고 제안했겠지만.. 지금은 그것도 빠듯하니까.
  - 어쨌든 proxy를 회원 기준으로 걸면 비회원이 대부분의 화면을 볼 수 없는 문제가 있어서, proxy를 일부 완화해 글쓰기만 막았다.
  - 비회원의 null 값이 와도 큰 문제가 없을 거라고 생각했다. 어차피 로그인하면 DB에 연결될 거고, 비회원은 사용하지 못하는 게 정상이니까.

### 11시 : 필수 기능 마무리

- 열심히 한 결과 다행히 시간에 맞추어 필수 기능을 구현할 수 있었고, PR을 진행한 뒤 간만에 좀 여유롭게 휴식할 수 있었다(PR #37).
- 점심 식후 배포 후 간단히 코드를 정리하고, 필수가 아니라 넘겼던 코드를 마저 작성하고(소셜 로그인은 시간상 통째로 진행하지 않기로 결정했다), 어젯밤을 새운 만큼 한숨 잠도 자고.. 그러려고 했지만...

### 13시 : null 값과 비회원 안내

- 밥을 먹고 와서 배포를 시작하자 문제가 생겼다. 나는 문제가 없다고 생각했던 null 값이 말썽이었다.
- 11시쯤 나의 PR이 적용되는 타이밍과 다른 파트가 새 브랜치를 내는 타이밍이 엇갈려, 적용된 브랜치 중 하나의 커밋이 과거의 것을 가져오는 문제가 있었다. 아무래도 11시에 붙여 넣은 파일들의 변동 사항이 좀 있었기 때문에 큰 오류가 있었던 것 같다. 다행히 그쪽은 무사히 해결되었다.
- 나 또한 가벼이 여겼던 비회원의 null 값을 처리하고, 로그인을 유도하는 알림을 띄우는 것으로 급히 바꾸었다.
  - 채팅은 입력창 자리에 "로그인하러 가기" 말풍선을 띄웠다.
  - 게시판은 화면을 열어 두고, 글·댓글·좋아요를 쓸 때만 로그인으로 유도하게 했다.

### 13시 후반 : 배포 성공

- 이후로 무사히 배포에 성공했다. 한시름 놓을 수 있었다. 이제 각자 마무리 단계에 들어가는 듯했다.
- 도중에 미구현하게 된 소셜 로그인 버튼을 팀원분의 요청에 따라 주석 처리해 보이지 않게 했다(PR #45).

### 14시 : 미뤄 둔 기능

- 이후 AI의 도움을 받아 후순위로 미루었던 코드 작성을 시작했다.
- 시간도 얼마 남지 않았고, 이제 더는 팀원에게 영향을 미치는 큰 변동의 작업은 하고 싶지 않았기에, 간단하게 보안 및 마이페이지 관련 부속 코드를 작성하는 데 집중했다.
  - 마이페이지에서 바꾼 사진이 헤더 프로필 동그라미에 뜨지 않던 문제를 고쳤다.
  - 로그아웃할 때 Spring 서버의 토큰도 무효화하게 했다.

### 15시 : AI의 게으름, 주석과 경고 정리

- 그러던 중 이놈의 AI가 또 게으름을 피워 코드를 제대로 읽지 않은 것을 발견했다. 교안의 A-3이 옛 코드 기준으로 쓰여 있었다.
  - 💭 이전부터 하네스 엔지니어링을 빠방하게 하고 싶다고는 생각했지만, 오늘은 또 한 번 격하게 생각하는 시간이 되었다. 이렇게 한 번 비틀림이 나기 시작하면 순식간에 쓸 수 없는 에이전트가 되기 때문에 속상했다.
  - 다행히 저번에 한 번 메모리를 비워서 그런지 크게 휘청이지는 않았고, 이어서 작업을 진행했다.
- 마무리 후 PR을 했다(PR #47).
- 도중에 코드 리뷰를 하던 팀원분께서 주석 정리를 요청하셔서, Auth 파트에서 만든 코드 전체를 훑어 주석을 정리했다.
- 어차피 디자인을 붙일 거라 신경 쓰지 않았었지만, 그래도 자꾸 Problems가 뜨는 게 신경 쓰여서 문제를 내고 있던 CSS 코드들을 정리했다.
  - 마이페이지 쪽의 문제도 수습하고 싶었지만, 3개 다 중요 코드인 것으로 보여 그만두었다.

### 16시 : 발표 공지

- 드디어 주석 정리를 마치고(PR #49) 잠시 30분 정도 눈을 붙이고 싶었지만, 매니저님이 오셔서 내일의 발표 공지를 하셨다. 울적했다.
- 그래도 슬슬 한계였기에 잠시 눈을 붙이고 발표 준비를 시작했다.
- 거창하게 하지는 않고, Auth와 마이페이지 파트를 어떻게 발표하면 좋을지 나름의 주요 코드와 API를 정리하기 위해 AI에게 소재와 대본 초본을 정리받았다.
- 중간에 어느 팀원분께서 우리 웹의 이름을 어떻게 할지 물어보셨고, 이후 결정된 이름에 따라 예쁘게 로고를 만들어 주셨다.
  - 💭 CSS로 만든 반응형 로고가 너무 예뻐서 행복했다.

### 17시 무렵 : 발표 자료 넘기기

- 팀원분 중 한 분께서 감사하게도 발표를 하시겠다고 말씀해 주셨다. 정리하던 대본과 자료들을 다시 한번 정리해 넘겨드렸다.
- 하지만 발표 후 질문 시간에는 내가 만든 부분은 내가 답변을 해야 할 테니, 열심히 내일을 준비하기로 했다.

### 18시 이후 : 디자인 정돈

- 하지만 곧 깨달았다.. 우리 팀은 결국 웹 디자인을 새롭게 붙이지 않아, 부끄러운 우리 집 클로드의 목업을 기본으로 한 디자인이 되어 있었다.
- 감사하게도 팀원분들께서는 마음에 들어 해 주셨지만 나는 아니었다.. 우리 팀의 얼굴이나 다름없는 웹에서 클로드 향기를 좀 걷어 내고 정돈된 분위기로 바꿔 주고 싶었다. 그래서 간만의 조기 귀가는 포기했다.
- 저녁 식후 다시 컴퓨터 앞에 앉았고... 똑같이 잔업을 하던 팀원분과 디스코드에서 온기를 나누며 함께 일을 했다.
- 💭 무척 졸리지만 그래도 어느 정도 만족스럽게 정돈된 디자인이 나왔다. 팀원분들도 좋아하셨으면 좋겠다.
