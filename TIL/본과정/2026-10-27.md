## HTML(HyperText Markup Language) 이란?
> 웹페이지의 뼈대와 구조를 담당하는 차세대 웹 표준 마크업 언어

### Markup 랭귀지
- 프로그램적 요소가 있는 마크업 랭귀지. 언어는 아님
- 어떠한 요소인지 정의하는 언어.
- 태그 : 꺾쇠로 감싼 표시
- 요소(element) : 여는 태그 + 내용 + 닫는 태그 전체
- 우리가 웹 화면에서 보는 글자, 버튼, 사진 하나하나가 다 요소임

```html
<!DOCTYPE html> <!-- HTML5 의 선언문 -->
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>문서 제목</title>
</head>
<body>
    <!-- 화면에 보여질 콘텐츠가 들어가는 자리 -->
</body>
</html>
```

| 코드 | 뜻 |
|---|---|
| `<!DOCTYPE html>` | "이 문서는 HTML5"라는 선언. 맨 첫 줄에 둠 |
| `<html lang="ko">` | 문서 전체를 감싸는 상자. `lang="ko"`는 한국어 문서라는 뜻 (화면 낭독기·검색엔진이 참고) |
| `<head>` | 화면에 **안 보이는** 정보 칸 (문서 설정) |
| `<meta charset="UTF-8">` | 글자 인코딩. 한글이 깨지지 않게 함 |
| `<meta name="viewport" ...>` | 휴대폰에서도 화면 폭에 맞게 보이게 함 (아래 반응형과 연결) |
| `<title>` | 브라우저 탭에 뜨는 제목 |
| `<body>` | 화면에 **보이는** 내용이 들어가는 칸 |
| `<!-- ... -->` | 주석. 사람만 읽는 메모, 화면엔 안 나옴 |

### HTML 의 역사
- 스티브잡스 : 웹 세계에 큰 파장을 일으킨 인물. 아이폰의 창시자로, 핸드폰에 웹을 이식함

  - 하지만 네이버의 모바일 버전은 반응형으로 나옴. 아이폰이 나오면서 출시

### 시맨틱태그(Semantic Tag)
> 이름만 보고도 어떤 역할과 위치인지 의미를 직관적으로 알 수 있게 만든 HTML5 요소

![시맨틱 태그 구조](./images/2026-10-27/04-semantic-tags.png)

| 시맨틱 태그 | 뜻 | 비유 (신문) |
|---|---|---|
| `<header>` | 머리글 (로고, 제목) | 신문 제호 |
| `<nav>` | 메뉴(내비게이션) | 목차 |
| `<main>` | 핵심 내용 | 본문 지면 |
| `<section>` | 주제별 구역 | 정치면, 스포츠면 |
| `<article>` | 독립된 글 하나 | 기사 하나 |
| `<aside>` | 곁다리 내용 | 옆 광고·박스 기사 |
| `<footer>` | 바닥글 (회사 정보, 연락처) | 맨 아래 발행 정보 |

### 웹 표준을 지켜야 하는 이유
- 크로스 브라우징(Cross Browsing) : 크롬, 엣지, 사파리, 파이어폭스 등 어떤 운영체제나 브라우저를 사용하더라도 동일하게 보이고 정상 작동하도록 보장
- 웹 접근성 향상 : 장애인이나 고령자를 포함한 모든 사용자가 기기나 브라우저에 구애받지 않고 정보에 접근할 수 있도록 돕는다
  - 구글의 검색엔진에 걸리기 위해선 웹 표준을 지켜야 함.
  - 검색에는 `<img>` 태그의 **alt** 속성을 많이 봄. 사회적 약자들도 사용할 수 있어야 한다.
- 유지보수 및 확장성 : 구조(HTML)와 표현(CSS)을 분리하여 코드가 간결해지고, 향후 수정이나 확장 작업이 쉬워짐
- 검색 엔진 최적화(SEO) : 검색결과가 위쪽에 잘 나오게 만듦. 의미에 맞는 시맨틱 태그(header, nav, section, footer 등)를 사용하여 검색 엔진이 웹페이지의 정보를 정확히 이해하게 만듦
  - 검색엔진이 페이지 구조를 이해하기 쉬울수록 유리함.
  - footer, address 등의 태그가 빠르게 찾아질수록 검색의 상위엔진으로 올라올 수 있다.

### 추가
- 태그는 정의를 다르게 해도 동작이 달라지진 않는다. 프론트엔드 개발자라면 이 태그 요소들이 컴포넌트 설계로 연결된다.
- 내 머릿속에 웹 표준과 시맨틱 태그 구조에 대해 숙지하는것이 유리하다.

## 스타일 시트(CSS)
> 웹 브라우저에 보는 모든 형태를 제어함. HTML이 설계도라면 CSS는 그 외의 나머지 건축정보

### CSS 기본 문법
```css
선택자 {
  속성: 값;
}

/* 예: 모든 버튼을 보라색으로 */
button {
  background-color: purple;
  border-radius: 8px;   /* 모서리 둥글게 */
}
```
- **선택자** = "누구에게" 입힐지 (button, .클래스이름, #아이디)
- **속성: 값** = "무엇을 어떻게" (색은 보라색으로)

### 역사
- 1994년에 만들어짐. 오래된 형식. 최근엔 함수도 도입됨
- 자바 스크립트나 html이 하던 일(마우스 올리면 색 바뀜, 애니메이션 등)을 일부 가져오고 있는 추세.

### 박스모델
> 기본적인 박스에 대한 정의. 패딩을 주든, 마진을 주든 기본 사이즈가 고정되는것

![박스모델](./images/2026-10-27/09-box-model.png)

- content = 사진
- padding = 사진과 액자 틀 사이의 흰 여백(매트)
- border = 액자 틀
- margin = 벽에 건 액자와 옆 액자 사이 거리
- "시계방향으로 돌아감" : 값을 4개 쓰면 **위 → 오른쪽 → 아래 → 왼쪽** 순서
  ```css
  padding: 10px 20px 30px 40px;  /* 위 10, 오른쪽 20, 아래 30, 왼쪽 40 */
  ```
  - 외우는 법 : 시계 12시(위)에서 시작해 3시(오른쪽), 6시(아래), 9시(왼쪽)

### hover와 a
- `:hover` = **마우스를 올렸을 때**의 모습을 정하는 CSS 문법. 커서가 바뀌거나 버튼의 색상이 바뀜
  ```css
  button:hover { background-color: violet; cursor: pointer; }
  ```
- `<a>` = **링크** 태그. 누르면 다른 페이지로 이동
- 프론트엔드를 한다면 버튼의 이벤트를 무엇을 부여할지 등, 적절한 선택을 하는 감각을 키워야 한다.
  - 이 버튼은 마우스를 올리면 색만 바뀌면 되는지, 눌러서 페이지를 옮겨야 하는지, 데이터를 보내야 하는지 **알맞게 고르는 눈**을 길러야 함

### CSS를 붙이는 3가지 방법

| 방법 | 쓰는 곳 | 예 | 비유 |
|---|---|---|---|
| **인라인 (inline)** | 태그 안에 직접 | `<p style="color:red">` | 옷에 직접 매직으로 칠하기 |
| **내부 (internal)** | `<head>` 안 `<style>` 태그 | `<style> p {color:red} </style>` | 집 안에 붙여 둔 인테리어 메모 |
| **외부 (external)** | 별도 `.css` 파일을 `<link>`로 연결 | `<link rel="stylesheet" href="mystyle.css">` | 여러 집이 같이 쓰는 인테리어 설계 파일 |

![CSS를 붙이는 3가지 방법](./images/2026-10-27/13-css-declare.png)

### tailwindcss
> CSS를 직접 쓰는 대신, 미리 만들어진 짧은 클래스 이름을 조합해서 꾸미는 도구. 현재 css 시각을 바꾸고 가장 많이 사용되는 도구

```html
<!-- 전통 방식 : CSS 파일에 따로 규칙을 써야 함 -->
<button class="my-button">로그인</button>

<!-- Tailwind : 클래스 이름만 보고 모양을 알 수 있음 -->
<button class="bg-purple-400 text-white px-4 py-2 rounded-lg">로그인</button>
```

- 현재 : 헤드에 정의하고 바디에는 클래스를 사용한다. 개발자들도 익숙해서 좋아함
  - HTML 에 클래스로 조합하여 그림을 그리는 기술.
  - 컴포넌트 기반인 React와 아주 잘 맞다.

## REACT
- 자바 스크립트 기반으로 만든 노드 기반의 라이브러리
- 요즘 웹 프론트엔드에 많이 사용
```
1. 코어 프레임워크 및 라이브러리 (Core Frameworks / Libraries)

웹 애플리케이션의 뼈대와 컴포넌트 구조를 만드는 핵심 도구입니다.
• React: 사용자 인터페이스(UI) 구축을 위한 가장 대표적인 라이브러리 (가상 DOM, JSX 사용)
```

```
	• 웹 페이지의 텍스트 변경, 이미지 애니메이션, 버튼 클릭 반응 등 동적 인터랙션을 처리합니다.
	• 쇼핑몰 장바구니 가격 자동 계산, 폼(입력창) 데이터 유효성 검사 등을 수행합니다.

	• 프론트엔드: 브라우저 안에서 동작하며, React, Vue.js 같은 프레임워크가 널리 쓰입니다.

• 특징: 동적 타이핑(Dynamic typing), 프로토타입 기반 객체지향, 싱글 스레드 기반의 비동기 처리 등을 지원합니다.
```

## React

- SPA : 싱글페이지 어플리케이션 기반
- React의 구조
  - html 안에 보통 소스코드가 많아야 동작
  - 리액트는 body 안에 div 하나가 있고 안에 id 'root' 라고 있음 -> index.js 가 html의 도큐먼트를 찾은 다음 app.js 로 실행하도록 만듦
  - javascript 기반
- csr을 제대로 이해하지 않는다면 동작 방식을 이해하기가 어려움
- React의 큰 단점 : 초기 구동이 느림. 모든 코드를 다운받아 오기 때문. 실행 이후에는 빠름.
- 훅
  - useState : '상태' 라는 용어
    - 함수체계의 코드. 데이터 체계에서 문제가 생김.
    - 자바스크립트는 불변성이 있음. 이를 해소하려고 나온 것.
    - 글자를 바꾸거나 할 때 변수처리를 해야함 -> useState 가 하나만 생기지 않음. 여러개가 나오고 상태지옥에 빠지는 상황이 생김(초기)

- 비동기 : 무작위 실행.

### 소스코드가 없음 순수 리액트는.
- 누군가가 열어보지 않으면 내용을 알 수 없음
- 검색내용이 없다는 말.
- 이후 검색엔진에 적합화 하기 위한 툴들이 개발됨
- 리액트만으로는 서버사이드 연결이 어렵다. 그렇기에 Next 또는 expo 등의 프레임워크 사용을 권장한다.
- 개발의 환경이 바뀌었다. 리액트만으로 사용하는 시기는 지났기 때문에 리액트 다음단계의 프레임워크를 알고 함께 사용할 수 있기를 바란다

### Next.js
- 리액트지만, 싱글페이지 기반이지만 페이지가 이동하고 소스코드가 나오고 검색을 할 수 있게 되면 좋겠어! 가 계기로 나온 프레임워크
- 장점 : 서버사이드 렌더링
  - csr 클라이언트사이드 렌더링 : 소스코드가 처음에 없다가 만들어지는 형태
  - ssr : 예시 - 쿠팡
    - 모든 웹사이트의 기반은 ssr. 소스 코드를 만드는 행위가 없음.
- ssr이 기본. 필요에 따라 csr을 사용하면 ux에 좋고 더 나은 웹사이트를 만들 수 있음
- Next의 만행 : 버전 바뀔때마다 뒤집힘
  - 오래된 버전을 사용하는 곳에 가게 되는 경우 page 라우터를 쓰는 경우도 있지만 되도록 앱라우터를 써라
- Next.js 만 쓸 수 있다면 훨씬 나이스한 웹을 만들 수 있다.
- 단순히 데이터를 뿌리기만 한다고 생각해선 안된다.
  - 데이터는 최종적으로 프론트엔드로 모인다. 조회, 호출 횟수 줄이기, 적합화, 안정화가 중요하고 캐싱기능이 아주 중요한 특징 중 하나임
- 캐싱 : 여러 앱 분산 처리
  - 서버동작 시 페이지가 열리는 것을 미리 인지하고 next.js의 단기메모리에 저장한다. db 호출을 줄인다. 한번도 조회하지 않는 db도 발생할 수 있다. 사람이 많을수록 유용한 기능. 물론 쿠팡 같은 큰 기업 페이지면 여러 서버가 필요하겠지만 DB의 부담이 훨씬 적은것은 마찬가지다.
  - 개발을 할 때 DB 부하를 줄이는 것을 전제로 백엔드를 개발함. 물론 DB 싱크 관련 기술들도 발전하고있지만 일반적으로 DB는 갑자기 늘리거나 줄일 수 없음.
  - 모든 기술은 DB가 멈추면 같이 멈춘다
- 화면에 그림이 그려질 때 가장 많이 데이터를 먹는게 무엇일까? 이미지, 영상임
  - 데이터가 아니라 파일.
  - 웹 서버에서 다운받아와야하는 데이터
- 넥스트는 화면에 보이는 것만 다운로드 받는다. 파일에 대한 커스터마이징-옵티마이제이션
- 주소창 활용을 잘 해야한다
  - 주소창엔 최대 5만자까지 들어감. 프론트에 들어갈 수 있는게 다 들어감
  - 프론트도 생각보다 보이지 않는 것이 많다.

- ai에게 녹음시켜 정리하는것도 좋긴 하지만 집중해서 듣고 이해하는 것이 베스트.
- HTML 개론에 대한 이야기
- JAVASCRIPT, CSS 어떤식으로 써야할지에 대한 이야기
- JavaScript의 웹표준
- html5와 css3의 이유를 알자
- TypeScript
  > JavaScript를 기반으로 구축된 강력한 타입 언어이며, 어떤 규모에서도 더 나은 도구를 제공합니다.
  - 자바 스크립트 사용시 좀 더 규칙을 엄밀하게 지켜보자 라는 용도. 자바스크립트의 자율성을 조금 자제시켜 복잡성과 변질가능성의 억제
- 프론트엔드의 문제 : 받아온 데이터를 자꾸 가공하려는 경향이 있음. 여기저기서 끌어오고. 이건 절대로 해선 안됨. 변질이 됨. 데이터에 대한 신뢰성이 훼손되는 문제를 경계해야 함. 받아온 데이터는 받아온 대로 가야한다. 백엔드도 마찬가지.
  - 원하는 데이터가 있다면 백엔드에 요청을 해야 한다.
  - 의존성이 생기면 힘든게 당연하다. 모르고 요청하는건 서로 동등한 입장에서 무례한 요청이다. 협업을 하려면 상대의 기술을 알아야 한다.
  - 풀스택에 필요한 기술이기도 함. 친절한 요청보단 명확한 요청을 하라
- 요즘 프론트엔드도 백엔드와 같은 기술을 쓰고 있다.
  - 엄밀하고 안전한 개발을 위해서.
  - 처음 설계가 중요하고 이 중에 api 설계가 포함되어 있음
- 타입스크립트를 써야하는 이유가 있음 필수는 아니라지만 대다수의 요즘 프로젝트가 타입스크립트 기반으로 만들어짐
  - 에이전트들이 타입스크립트 선언을 도와주기도 하니 두려워말고 공부해라
- REACT : 서버액션 동작을 중요하게 봄.
  - 동기 비동기 처리를 알아야 하기 때문에 useTransition 같은 기능을 제공함 : 현재 액션을 했을 때 동작을 하고있는지 끝났는지 알려주는 기능
    - 생긴 이유 : 로그인 버튼을 클릭을 하면 데이터가 송출 됨. api요청 중 단추를 비활성화하거나 하지 않으면 두번 클릭이 가능함
    - 물론 이걸 동기화 시킬수는 있지만 대신 소스코드가 늘어남
    - 이런 소스코드를 줄여주려고 나온 것이 useTransition. 로그인중.. 이라고 뜨거나 버튼이 바뀌는 식으로 소스코드를 덜어내는 방향이 생김.
- 프론트엔드는 기획팀과 많이 싸운다
  - 검색시 특수문자들이 가능한지, 몇 자까지 가능한지
  - 아이디와 비밀번호가 틀렸을 때 두루뭉술하게 전달하여 보안책을 사용.
  - 그런데 아이디나 비밀번호 중 어느쪽을 카운트해야할까? 보통 비밀번호임.
  - 전체적인 흐름을 이해하면 좀 더 정확한 요구를 할 수 있다. 로그인이랑 회원가입만 가도 머리가 터짐.
  - 요즘 신입 기피하는 현상이 생기는 이유중 하나. 이런 현업의 디테일한 요소를 가르치는 피로감.
- 요즘은 프론트엔드도 엄밀하게 개발해야 한다. 그 기술을 쓰는 이유를 알고 사용하자.
- HTML, CSS, React 병행하며 수업 진행예정

## 오늘 수업 한눈에 보기
오늘은 **웹 화면이 무엇으로 만들어지는지**를 처음부터 훑은 날. 집 짓기로 비유하면 다음과 같다.

| 기술 | 집 짓기 비유 | 하는 일 |
|---|---|---|
| **HTML** | 뼈대·기둥 (설계도) | "여기는 제목, 여기는 버튼" 하고 **무엇이 있는지** 정함 |
| **CSS** | 페인트·인테리어 | 색, 크기, 배치 같은 **어떻게 보일지** 정함 |
| **JavaScript** | 전기·수도 (움직이는 장치) | 버튼을 누르면 무언가 **일어나게** 함 |
| **React** | 조립식 건축 공법 | 화면을 부품(컴포넌트)으로 나눠 **효율적으로** 만들고 바꿈 |
| **Node.js** | 공사장 밖에서도 쓰는 전동공구 | 브라우저 **밖에서도** JavaScript를 실행 |
| **npm** | 공구·부품 상점 | 남이 만든 도구(React 등)를 **내려받음** |
