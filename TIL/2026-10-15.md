## 2강 : 클라이언트와 서버

### 웹 서비스 기본 흐름
- 사용자의 요청은 서버에서 처리됨

> [!] 웹 서비스 기본 흐름
> 1. 사용자 요청 단계
        - 사용자가 브라우저(또는 앱)에 URL입력 또는 버튼/링크 클릭
        - 브라우저가 DNS서버에 요청 > 해당 도메인의 IP 주소 조회
        3. 브라우저가 해당 서버로 HTTP/HTTPS 요청 전송
>
> 2. 서버 처리 단계(ORM 포함)
        1. 웹 서버(Nginx,Apache 등)
            - 클라이언트 요청을 받아 정적 리소스(HTML, CSS, JS, 이미지 등) 전달
            - 또는 애클리케이션 서버로 요청 전달

#### URL
- 네이버나 다음 등 각 도메인에는 4~6자리의 IP라는 숫자가 존재함. 일종의 컴퓨터 집주소.
- 일반적으로 사용자들은 IP 숫자들을 알지 못함
- 그렇기 때문에 이 IP를 특정 이름의 도메인(DNS)이라는 주소에 바인딩한다
- 사용자들은 브라우저를 사용해 편하게 특정 도메인 주소(URL)를 이용해 요청함.
- 웹 : http, 보안을 신경쓰면 https(+secure) 라는 프로토콜을 이용해 요청하게 됨.
- url을 이용해 사용자가 요청하게 되면, 이 요청은 백엔드가 받게 됨.

#### 웹서버
- 요청을 위해 상시 대기하고 있음.
- app
- 요청 전달 역할

#### 웹 서버와 웹 어플리케이션 서버의 차이
- Web Server: 정적 리소스(HTML, image, javescript, css) 를 관리하는 서버
    - 주 사용: Apache, Ngnix. 주로 무료로 제공됨
- Web Application Server : WAS - 동적 리소스(java 기반인 경우 -jsp, servelet, etc...)를 관리하는 서버. + 웹서버
    - 주 사용: ORACLE의 웹로직, IBM 웹스피어, TMAX의 제우스. 대개 비용이 높음

- 대체로 WAS로 이해하는 것이 맞음

```
사용자(브라우저) -- HTTP프로토콜 -- > Web Server ----> 정적리소스를 처리하는 WAS(어플리케이션서버)
```

- Was 안에 사용자들의 요청을 처리할 수 잇는 프로그램(jsp, servelet, etc...)들이 들어있음.

> 2. 서버 처리 단계(ORM 포함)
        2. 애플리케이션 서버 (Spring Boot 등)
            - 컨트롤러 > 서비스 > 리포지토리 흐름으로 요청 처리
            - 이때 DB와 직접 SQL 을 작성하지 않고, ORM(Object Relational Mapping) 기술을 활용해 데이터 접근
            - ORM : 객체와 관계형 데이터베이스를 매핑하는 기술
                - 개발자가 SQL을 직접 작성하지 않고 객체 중심 코드로 DB 접근 가능
                - DB 테이블 <> 클래스, 컬럼 <> 필드 로 매핑됨
            - 주요 ORM 도구
                - JPA(Java Persistence API) : 객체 지향 중심 SQL 자동 생성(추상화 높음)
                    - 자바 진영의 표준 ORM 인터페이스
                    - 구현체: Hibemate 등
                    - 객체지향적으로 데이터 처리 > SQL을 직접 다룰 필요가 줄어듦
                    - 예 : userRepository.findById(1L);
                - MyBatis : SQL 중심, 직접 제어 가능(유연성 높음)
                    - ORM 이라기보다 SQL 매퍼 성격이 강함
                    - SQL은 직접 작성하지만, 결과를 객체와 매핑해줌
                    - SQL은 최적화/제어가 필요한 경우 선호
                    - 예: SELECT * FROM users WHERE id = #(id) -> User 객체에 매핑
