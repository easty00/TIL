#### 나 자신을 알라

    - **비전공자**라면 : 
        - 개념 이해 → 따라 하기 → 변형 → 나만의 코드
        - 강의를 반복 시청하며 이해를 하는것이 중요함
        - 학습질문란에 질문 많이 해라
        - 코드 복붙하지 말고 직접 많이 타이핑 해보기
        - AI는 '설명해 주는 튜터'로만: "이 코드 한 줄씩 설명해줘"는 OK, "만들어줘"는 금지
        - 첫 TIL 주제: "나는 왜 개발을 배우는가?"
    - 입문자라면 :
        - 공식 문서를 먼저 훑어보고 강의를 들어라.
        - TIL에 "왜?"를 반드시 함께 기록
        - AI 리뷰 전에 **'내가 예상한 문제점 3개'** 를 먼저 적고 AI 답과 비교
    - 전공자, 경험자라면 :
        - 아키텍처 관점으로 수업 내용 연결·분석 공식 문서·RFC·릴리스 노트를 직접 읽는 습관
        - 코딩 에이전트로 리팩터링 → diff를 한 줄씩 리뷰하는 훈련

#### AI 사용 3단계 레벨 - 언제 어디까지 쓰는가
| 레벨 | AI 의 역할 | 사용법 | 금지사항 |
| --- | --- | --- | --- |
| L1 튜터 | 개념 설명 · 에러 메시지 해석 | "이 개념을 이렇게 이해했는데 맞아? 틀린 부분만 짚어줘", 에러 전문을 붙여 "원인을 설명만 해줘" | 코드 생성 요청, 과제 답안 생성 |
| L2 리뷰어 | 내 코드 리뷰 · 대안 제시 · 테스트 아이디어 | 내 코드가 먼저 → 리뷰 요청 → 이유를 이해한 것만 반영. 반영한 내용은 TIL에 "AI 제안 / 내 판단"으로 기록 | 이해 못 한 코드 붙여넣기 |
| L3 에이전트 협업 | 스펙 기반 구현 · 테스트 · 리팩터링 실행 | 스펙 작성 → 계획 먼저 확인 → 작은 단위로 실행 → 빌드·테스트·diff 리뷰 → PR에 기록 | 리뷰 없는 머지, 내 담당 코드를 설명 못 하는 상태 |

#### 개발 언어의 역사와 원리
- 1800 년대 산업혁명
    - 증기기관 개발. 기계를 어떻게 조종할까? 고민하며 최초의 알고리즘 등장. 
    - 기계는 정해진 지시만 정확히 따른다 : JAVA 개발의 시초
- 1950-60 년대 기계어에서 인간어로
    - 사람어를 기계어로 번역 시작
    - CODE, SQL
- 1970-80 년대 구조화, 객체지향(OOP) 등장
    - 코드가 복잡해지기 시작
    - C, C++, JAVA
- 1990~2000 년대 인터넷혁명.웹과 스크립트
    - JAVA SCRIPT
- 2010 년대 클라우드, 모바일, 프레임워크의 전성시대 (스마트폰)
    - Spring Boot·React
    - TypeScript(2012) : 설정코드를 줄이자
- 2020년대 초 AI가 코드를 제안하다
    - AI 가 코드 만들기 시작
- 2025년~ 에이전트 시대 · 자연어와 스펙이 새 인터페이스
    - 개발자는 마크다운으로 목표 · 범위 · 제약 · 완료 조건 (스펙)을 쓰고 결과를 검증
    - 원리가 더 중요해짐


#### 문법에는 이유가 있다.
- 세미콜론 ; , 중괄호{} : 기계가 추측하지 않게 하기 위함
- 타입 선언 : 잘못된 값 방지, 메모리 크기 지정
- class, private : 데이터와 기능 묶음, 복잡한 정보를 구조적으로 관리
- interface

#### 원리를 이해하면 문법이 따라온다
- 암기 대신 "왜?" 부터. 원리와 배경을 알고 질문에 대해 답을 할 수 있다면 더욱 이해하기 쉽다.
- 강의 전에 먼저 검색해보고 에러 메시지들을 한국어로 풀어보기
- 오늘 배운 문법이 존재하는 이유를 TIL에 한줄 정리
- @Service 가 붙는 이유를 알기
- 공식 문서에서 "내가 아는 개념의 다른 이름" 찾기
- "왜 이 코드를 여기에 쓰는가?" 를 설명 정리 해보기
